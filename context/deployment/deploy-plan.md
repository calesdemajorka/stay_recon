## What's Deployed

Bare Django 6.1.1 scaffold — no custom app/models yet (out of scope for this
deploy; tracked as future feature work). `/` serves a static placeholder
landing page (plain view, `stay_recon/views.py::index`) so the root URL no
longer 404s while the real product UI is built out. `/healthz/` is a plain
view in the same module (not a Django app: no `INSTALLED_APPS` entry, no
migrations) that runs `SELECT 1` through Django's real DB connection,
proving gunicorn → Django → Postgres wiring end-to-end. `/admin/` is mounted
and redirects to login as expected; no superuser has been created. Static
files are served via WhiteNoise (`CompressedManifestStaticFilesStorage`) —
only Django's own admin assets exist so far, no custom static files. Only
Django's built-in migrations (`admin`, `auth`, `contenttypes`, `sessions` —
18 total) have run; no domain schema exists yet.

Initial deploy: commit `63e0041` ("Prep Django scaffold for first Render
deploy"), deploy id `dep-dah8hr9t0dsc73f1d070`, triggered by
`blueprint_sync`, live within ~71 seconds of Blueprint launch.

Follow-up deploy: commit `0bdf1e7` ("Add placeholder landing page at /"),
deploy id `dep-dah8qc49v7es73b9npbg`, triggered automatically by
`new_commit` (`autoDeployTrigger: commit`), status `live`, built in 47s —
first real-world confirmation that routine `git push` → auto-deploy works
unattended, no human gate needed.

Config-only deploy: commit `7e2b7ff` ("Add buildFilter to skip rebuilds on
docs-only changes") added a `buildFilter` to `render.yaml`, scoping builds
to app-code paths (`manage.py`, `stay_recon/**`, `build.sh`,
`pyproject.toml`, `uv.lock`, `.python-version`, `render.yaml`). This push
produced two deploys: `dep-daha8dvavr4c73e929eg` (`new_commit`, rebuilt the
app, `live`) and `dep-daha8e1al16s73crhlt0` (`service_updated`, registers
the filter itself — config sync, no rebuild). From this point on, pushes
touching only `context/`, `AGENTS.md`, `CLAUDE.md`, `.claude/`, or other
non-listed paths no longer trigger a build.

## Operational Story

- **Deploys**: `git push` to `dev` → Render's native git-based auto-deploy
  (`autoDeployTrigger: commit` in `render.yaml`), gated by a `buildFilter`
  allowlist so only app-code changes rebuild the service — docs/context-only
  pushes are skipped. No GitHub Actions CI wired yet — separate, tracked in
  `tech-stack.md`'s `ci_default_flow` hint, not part of this deploy.
- **Secrets**: `SECRET_KEY` auto-generated by Render (`generateValue: true`);
  `DATABASE_URL` auto-wired via `fromDatabase` → `connectionString` (internal
  URL, same region). Neither was typed or committed anywhere. `DEBUG=False`
  set explicitly in `render.yaml` for production.
- **Logs**: `render logs` (CLI, once authenticated) or the Render MCP
  server's `list_logs` (read-only, already connected this session).
- **Rollback**: no dedicated rollback verb on Render — redeploy an earlier
  commit from deploy history. Carried over from `infrastructure.md`: if a
  migration ran between the two deploys, the redeployed code may not match
  the current schema — treat any rollback crossing a migration boundary as
  manual and schema-checked, not one-click. Not yet exercised.
- **Approval**: routine deploys (`git push` → auto-deploy) run unattended
  going forward. Creating/deleting services, upgrading plans, and rotating
  the Postgres connection string remain human/dashboard actions.

## Explicitly Deferred (tracked, not executed in this deploy)

- **Paid-tier upgrade (web service + Postgres)** — deliberate, not an
  oversight. Concrete triggers:
  - **Postgres free-tier expiry: 2026-10-10** (confirmed via Render's own
    `expiresAt` field, exactly 30 days from creation) — upgrade well before
    this date; do not rely on the 14-day post-expiry grace period.
  - **Before any participant-facing use** — the free web service spins down
    after 15 min idle; a 30–60s cold start on the next request directly
    breaks the PRD's "suggested room within 2 seconds" NFR. Fix is a paid
    Starter instance, not a keep-alive ping (research confirms Render itself
    doesn't endorse external ping workarounds as a substitute).
  - **Before any real user/participant data is created** — no automated
    backups exist on the free Postgres plan.
  - Re-check `render.com/pricing` before upgrading — `infrastructure.md`
    flagged an April 2026 pricing restructure that may make older cost
    assumptions stale.
- Django app/models (events, bookings, CSV upload — FR-002 etc.) — future
  feature work, entirely out of scope for this deploy.
- GitHub Actions CI wiring — separate from Render's own auto-deploy.
- Render Cron Jobs (link-expiry, GDPR-retention sweeps) — blocked on
  management commands that don't exist yet.
- Object storage (S3/R2) for CSV uploads — blocked on FR-002, not
  implemented.
- Custom domain — the `onrender.com` subdomain is sufficient for now.
